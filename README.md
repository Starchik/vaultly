# Vaultly — приватный файлообменник с шифрованием нулевого разглашения

Полноценный файловый менеджер с шифрованием на стороне клиента, публичными
ссылками и собственным тёмным интерфейсом (индиго/циан на графитовом фоне,
монохромные иконки из единого набора Lucide).

## Возможности

- Регистрация / вход (JWT, пароли хранятся как bcrypt-хэши)
- **Настоящее end-to-end шифрование файлов**: каждый файл шифруется в
  браузере (AES-256-GCM, Web Crypto API) ДО отправки на сервер. Сервер
  хранит только зашифрованные байты и зашифрованные метаданные (имя,
  тип) — прочитать содержимое или имя файла сервер не может.
- Ключ шифрования каждого файла хранится в "обёрнутом" виде — зашифрован
  мастер-ключом, который выводится из вашего пароля (PBKDF2) и никогда не
  покидает браузер.
- **Вход по биометрии (WebAuthn + PRF)**: Face ID / Touch ID / Windows
  Hello / отпечаток на Android разблокируют хранилище БЕЗ пароля и БЕЗ
  ввода логина. Это не просто подтверждение личности — расширение PRF выводит из
  аутентификатора детерминированный секрет, которым на клиенте обёрнут
  мастер-ключ шифрования. Сервер видит только обёрнутый мастер-ключ и
  публичный ключ WebAuthn-credential, сам секрет никогда не покидает
  устройство. Поддержка PRF зависит от браузера/устройства (хорошо у
  свежего Chrome/Android, ограниченно у Safari/iOS) — если её нет,
  приложение честно сообщает об этом, а не имитирует защиту.
  Ключ доступа регистрируется как discoverable (resident key): устройство
  хранит его вместе с `userHandle`, поэтому на странице входа достаточно
  нажать «Войти по биометрии» с пустыми полями — или выбрать ключ доступа
  прямо в поле логина, браузер предлагает его сам (conditional UI).
  Ключи, добавленные до появления этого режима, вход без логина не умеют —
  удалите их в разделе «Биометрия» и добавьте устройство заново (в списке
  они помечены как «с вводом логина»).
- **PWA**: устанавливается на телефон/десктоп как приложение, работает
  офлайн для интерфейса (сама передача файлов, конечно, требует сети).
- **Полноценная мобильная версия**: боковая панель на телефоне становится
  выдвижным меню, топбар перестраивается в несколько строк, список файлов
  сжимается, все кнопки увеличены под тап. Открытие папки/файла — по
  одиночному тапу (не по двойному, который на мобильных браузерах обычно
  зумит страницу). У каждой карточки/строки есть кнопка «⋮» для контекстного
  меню — без ненадёжного long-press. Плавающая кнопка загрузки всегда под
  рукой, без необходимости открывать меню.
- Публичные ссылки `share.html#<id>!<ключ>` — ключ передаётся во фрагменте
  URL, который браузер физически не отправляет на сервер. Сервер не может
  расшифровать файл, даже если захочет.
- **Настройки публичной ссылки**: срок действия (1 час / 24 часа / 7 дней /
  30 дней / без ограничения), лимит скачиваний и необязательный пароль.
  В режиме с паролем ключа в ссылке **нет** совсем: она выглядит как
  `share.html#<id>`, а ключ файла обёрнут ключом из пароля
  (PBKDF2-SHA256, 150 000 итераций) и хранится на сервере в обёрнутом виде.
  На сервер уходит только «верификатор» — вторая половина того же
  PBKDF2-вывода, и хранится он как SHA-256, поэтому сам пароль и ключ
  обёртки серверу неизвестны. Онлайн-перебор ограничен: 10 попыток за
  5 минут на ссылку.
- **Предпросмотр медиа**: картинки, видео и звук открываются прямо в
  приложении — файл расшифровывается в браузере и отдаётся `<img>`/
  `<video>`/`<audio>` через `blob:`-URL. Для остальных типов поведение
  прежнее — скачивание.
- **Мультивыбор и массовые операции**: чекбокс на карточке, `Ctrl/⌘+клик`,
  `Shift+клик` (диапазон), `Ctrl/⌘+A`; над списком появляется панель с
  действиями — скачать, скачать ZIP, переместить, в корзину (в корзине —
  восстановить / удалить навсегда). На всю пачку — одна нотификация.
- **Перетаскивание между папками**: файлы и папки можно тащить на папку или
  на «крошку» в навигации. Перемещение папки внутрь самой себя (на любой
  глубине) отсекает сервер, а не только интерфейс.
- **Скачивание папки одним ZIP** — архив собирается в браузере, файлы
  расшифровываются по одному и сразу пишутся в поток (File System Access
  API, если браузер его поддерживает), поэтому целиком в памяти архив не
  держится. Вложенные папки сохраняют структуру, пустые тоже попадают в
  архив.
- Папки, переименование, drag-and-drop загрузка (с постоянной подсказкой),
  сетка/список, поиск, контекстное меню с иконками, корзина (мягкое
  удаление + восстановление + автоочистка по сроку), квота хранилища с
  индикатором и отдельной строкой «в корзине».
- Собственный фирменный стиль: тёмный интерфейс, акцент — градиент
  индиго → циан, единый набор монохромных SVG-иконок (Lucide, ISC-лицензия)
  вместо эмодзи — folder/file/upload/download/link/trash и т.д.

## Важные упрощения

- Имена **папок** не шифруются (только файлы — имя, тип и содержимое).
- Хранилище метаданных — простой `db.json`, а не промышленная СУБД.
  Подходит для дома/хобби-проекта, не для продакшена с нагрузкой.
  Все изменения идут через одну очередь (мьютекс) и записываются атомарно
  (запись во временный файл + `rename`), поэтому параллельные запросы не
  затирают друг друга, а обрыв процесса не оставляет обрезанный `db.json`.
- Мастер-ключ на клиенте живёт в `sessionStorage` (очищается при закрытии
  вкладки) — упрощённый вариант вместо полноценной модели сессий.
- **Корзина занимает квоту.** Удалённые файлы продолжают лежать в
  `storage/`, поэтому «занято» после удаления не уменьшается — в сайдбаре
  видно отдельной строкой, сколько освободится. Освобождает место
  «Очистить корзину» или автоматическая уборка через `TRASH_TTL_DAYS`
  (по умолчанию 30 дней).
- **Счётчик скачиваний по ссылке считает начатые загрузки.** Оборванная на
  середине загрузка тоже расходует лимит — иначе счётчик обходился бы
  простым разрывом соединения.
- **ZIP собирается без Zip64**, поэтому при суммарном объёме (или размере
  одного файла) от 4 ГБ приложение честно откажется собирать архив и
  предложит скачать файлы по отдельности.
- **Пароль на ссылке защищает от посторонних, но не от владельца сервера.**
  Ключ файла хранится обёрнутым паролем: тот, у кого есть `db.json`, может
  перебирать слабый пароль офлайн, и рейт-лимит ему не помешает. Для
  ссылки с паролем выбирайте длинную парольную фразу — или используйте
  обычный режим, где ключ вообще не покидает саму ссылку.
- Нет двухфакторной аутентификации, шаринга папок целиком, версионирования
  файлов — при желании дорабатывается поверх.
- Видео для предпросмотра скачивается **целиком**: AES-GCM применён ко
  всему файлу сразу, поэтому играть его по частям нельзя. Для файлов больше
  200 МБ приложение сначала спрашивает подтверждение.
- Забытый пароль = потеря доступа к файлам (это следствие настоящего
  end-to-end шифрования, а не баг — сервер не знает ваш ключ). Биометрия
  на новом устройстве не поможет восстановить старые файлы без пароля —
  её нужно один раз включить на каждом устройстве, пока пароль ещё известен.
- JWT-секрет сохраняется в файле `server/.jwt-secret` (создаётся
  автоматически при первом запуске) — не удаляйте его, иначе все
  выданные токены (обычные и биометрические) станут недействительными и
  всем придётся войти заново.

## Исправленные баги (по сравнению с первой версией)

- **Все запросы падали с «Требуется авторизация»** (создание папки,
  загрузка файлов, объём хранилища завис на «Загрузка…») — `api.js`
  читал токен из старого ключа `sessionStorage`, оставшегося после
  переименования проекта. Сейчас исправлено; при истечении сессии
  приложение теперь явно перекидывает на экран входа вместо тихого сбоя.
- JWT-секрет генерировался заново при каждом перезапуске сервера, что
  моментально делало недействительными все выданные токены — теперь
  секрет сохраняется на диск и переживает перезапуски.
- Иконка поиска съезжала из-за отсутствующего вертикального центрирования.
- Кнопка «Выйти» перенесена к логотипу, теперь это иконка без подписи.
- Добавлена постоянная (не только при активном перетаскивании) подсказка
  о поддержке drag-and-drop.

## Запуск

```bash
cd server
npm install
npm start
```

Сервер поднимется на `http://localhost:7860` и сам раздаёт папку `public/`
(фронтенд), так что открывать нужно именно этот адрес — отдельный
статический сервер не требуется.

Тесты:

```bash
cd server
npm test
```

Это `node --test test/` — встроенный тест-раннер Node, никаких внешних
зависимостей для тестов не нужно. Каждый тест поднимает сервер на случайном
порту в собственном временном `DATA_DIR`, так что рабочие данные не
затрагиваются. Покрыты авторизация, папки, файлы, квота, корзина и её
автоочистка, публичные ссылки (срок, лимит, пароль) и параллельная запись
в `db.json`.

По умолчанию квота — **100 ГБ** на пользователя (меняется константой
`DEFAULT_QUOTA_BYTES` в `server.js`).

### Переменные окружения (необязательно)

- `PORT` — порт сервера (по умолчанию **7860** — так на Hugging Face
  Spaces приложение отвечает без дополнительных настроек; Render и
  подобные платформы обычно передают порт через эту же переменную сами)
- `DATA_DIR` — куда сервер пишет данные (`db.json`, `.jwt-secret`, папка
  `storage/` с зашифрованными файлами). По умолчанию — рядом с
  `server.js`. **На платформах с эфемерной файловой системой** (Render
  без диска, Hugging Face Spaces без Persistent Storage) всё, что здесь
  лежит, стирается при каждом передеплое/перезапуске контейнера — если
  подключили постоянный том, укажите его путь через эту переменную
- `JWT_SECRET` — секрет для подписи JWT. По умолчанию генерируется один
  раз и сохраняется в файл `.jwt-secret` внутри `DATA_DIR` — переживает
  обычные перезапуски процесса. Но если сама файловая система эфемерна
  (см. выше), при каждом передеплое секрет всё равно будет новым, и все
  выданные токены/сессии станут недействительными — чтобы этого избежать,
  задайте `JWT_SECRET` вручную (любая случайная строка) как секрет
  платформы, а не полагайтесь на автогенерацию
- `TRASH_TTL_DAYS` — через сколько дней содержимое корзины удаляется
  окончательно (по умолчанию **30**). Уборка запускается при старте
  сервера и затем раз в 6 часов. `0` отключает автоочистку — тогда
  корзина будет занимать квоту до ручного «Очистить корзину»

## Деплой на Hugging Face Spaces (Docker)

В репозитории уже есть `Dockerfile` и YAML-фронтматтер в начале этого
файла (`sdk: docker`, `app_port: 7860`) — Hugging Face использует их
автоматически.

1. На [huggingface.co/new-space](https://huggingface.co/new-space) выбери
   SDK **Docker** (шаблон Blank), задай имя.
2. Склонируй появившийся пустой репозиторий Space и запушь в него
   содержимое этого проекта (или подключи существующий GitHub-репозиторий
   через настройки Space → Repository).
3. Space соберёт `Dockerfile` и запустит контейнер — дальше ничего
   настраивать не нужно, порт и SDK уже прописаны в README.

**Важно:** бесплатные Spaces используют эфемерную файловую систему —
после каждого передеплоя (или долгого простоя, если Space засыпает)
`db.json`, `.jwt-secret` и загруженные файлы обнулятся. Чтобы данные
сохранялись, подключи Persistent Storage (Settings → Storage) и укажи
точку монтирования через переменную окружения `DATA_DIR` (Settings →
Variables and secrets), например `DATA_DIR=/data`.

## Деплой на Render

1. **New → Web Service**, подключи репозиторий.
2. **Root Directory**: `server`
3. **Build Command**: `npm install`
4. **Start Command**: `node server.js`
5. Render сам передаёт порт через `PORT` — сервер уже это учитывает.

Как и на Hugging Face, диск на Render по умолчанию эфемерный — для
сохранности данных между деплоями подключи **Render Disk** и укажи путь
монтирования через `DATA_DIR`.

## Деплой рядом с HUB NAS

Т.к. это отдельный Node.js-сервис, его можно поднять как ещё один сервис
в вашем стеке HUB NAS: добавить в docker-compose/systemd (готовый
`Dockerfile` в корне репозитория подходит и для этого), пробросить порт
и, если нужно, вывести наружу через тот же Cloudflare Tunnel отдельным
поддоменом (например `vault.nextnas.pp.ua`) — по аналогии с остальными
сервисами (`chat.`, `docker.`, `apps.`). Здесь файловая система обычная
(не эфемерная), так что `DATA_DIR` можно не трогать.

## Структура проекта

```
vaultly/
  Dockerfile          — сборка для Hugging Face Spaces / Render / любого Docker-хостинга
  .dockerignore
  server/
    server.js        — Express API: auth, папки, файлы, шаринг, WebAuthn
    package.json
    db.json           — создаётся автоматически при первом запуске
    .jwt-secret        — создаётся автоматически, хранит секрет для JWT
    storage/           — зашифрованные блобы файлов (создаётся автоматически)
    test/               — тесты на встроенном node --test (helpers.js + *.test.js)
  public/
    index.html         — вход/регистрация
    app.html            — облачный диск
    share.html           — публичная страница по ссылке
    manifest.json         — PWA-манифест
    sw.js                  — service worker (офлайн-кэш статики)
    icons/                   — PNG-иконки PWA разных размеров
    css/style.css
    js/icons.js          — единый набор монохромных SVG-иконок (Lucide)
    js/crypto.js           — AES-GCM/PBKDF2 в браузере
    js/api.js                — обёртка над fetch
    js/auth.js                 — логика входа/регистрации
    js/app.js                    — логика диска (загрузка/шифрование/UI)
    js/preview.js                  — предпросмотр картинок/видео/звука
    js/zip.js                        — сборка ZIP-архива в браузере
    js/share.js                        — логика публичной страницы
    js/webauthn.js                       — биометрия (WebAuthn + PRF)
    js/webauthn-browser.js                 — клиентская библиотека WebAuthn (бандл)
    js/pwa.js                                — регистрация service worker
```

## О брендинге и иконках

Название, цветовая палитра и логотип — авторские, разработаны для этого
проекта. Иконки взяты из открытого пакета [Lucide](https://lucide.dev)
(ISC-лицензия) — единый набор линейных монохромных иконок, встроены
инлайн в `js/icons.js`, поэтому проект не зависит от внешних CDN и
работает офлайн.
